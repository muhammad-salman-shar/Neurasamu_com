Synapse AI Memory Graph (SMG v2)

Architectural specification for episodic, pointer-virtualized long-term memory in large language models.

Abstract

Modern Large Language Model deployments suffer from a fundamental limitation: context saturation. As conversational agents interact with users over weeks, months, or years, accumulated history quickly exceeds the model's physical context window. Existing solutions trade off between brute-force token cost and lossy summarization. SMG v2 proposes a dual-tier architecture that decouples conversation persistence from active generation — a strictly bounded sliding window for immediate dialogue, and a pointer-virtualized storage vault for historical events. Memory is not deleted or summarized; it is virtualized. Episodic recall remains exact while the generation-time prompt stays bounded.

Design Thesis

Virtualize long-term memory rather than stuffing it into the context window: keep a bounded active buffer, index evicted turns through atomic semantic pointers, and page only the exact historical payload required at inference time.

1. Executive Summary & Problem Formulation

Modern Large Language Model deployments face a fundamental limitation: context saturation. As conversational agents interact with users over weeks, months, or years, accumulated dialogue history can exceed the model's practical context budget. Two common strategies introduce important trade-offs:

  • Brute-Force Context Stuffing: replaying raw multi-turn histories scales with retained tokens — increasing inference expense while degrading retrieval quality when many unrelated details compete for attention.
  • Lossy Summarization: compressing historical interactions into high-level prose reduces token load but destroys atomic facts and exact episodic details required for granular recall.

SMG v2 Solution. A dual-tier execution architecture decouples conversation persistence from active generation. A strictly bounded sliding window handles immediate dialogue, while a pointer-virtualized storage vault preserves historical events. Evicted interactions are indexed using atomic keywords and unique IDs; the full payload remains outside the active prompt and is demand-paged only when needed.

Design Objective

The architecture aims to preserve long-horizon episodic recall while keeping the generation-time prompt bounded. The core mechanism is not deletion or summarization of memory — it is virtualization of memory access.

2. Core Architecture & Structural Memory Model

SMG v2 is organized around three foundational pillars: the L1 Active Buffer, the L2 Keyword Box, and the L2 Chat Store. Together they separate short-term generation state from durable episodic memory.

Pillar 1 — L1 Active Buffer (The Sliding Window)

The Active Buffer resides directly in the LLM's volatile context window. It is strictly capped at a 4-turn interaction window, where each turn consists of an input/output pair. When a fifth interaction begins, the oldest interaction is evicted from the active prompt. This bounds the amount of historical text processed during ordinary generation.

Pillar 2 — L2 Keyword Box (The Semantic Index)

When an interaction is evicted, an asynchronous process extracts approximately 3–7 atomic keywords plus compact semantic metadata. The resulting Keyword Bundle receives a unique ID (for example, SGO100002345). The semantic representation can be persisted in a vector index, while a low-latency key-value or graph layer accelerates pointer resolution.

Pillar 3 — L2 Chat Store (The Virtualized Vault)

The complete input/output payload is stored separately from the semantic index. The same unique ID is attached to the raw payload, creating a strict pointer-mapping relationship: the Keyword Box identifies what an event is about; the Chat Store contains what actually happened.

3. Runtime Execution Lifecycle

Phase 1 — Ingestion & Async Tagging (Turns 1–4)

During active conversation, the latest turns remain in volatile context. In parallel, background workers extract canonical tags, micro-context, and metadata without blocking the generation path. Each interaction receives a stable ID that can reference both its semantic record and raw payload.

Phase 2 — Eviction & Bifurcated Storage (Turn 5 Onward)

When Turn 5 begins, Turn 1 leaves the active prompt. Its raw input/output is persisted in the Chat Store, while its Keyword Bundle is persisted in the semantic index. Both records retain the same identifier — for example, SGO100002345. The cycle repeats indefinitely.

Phase 3 — Demand Paging Retrieval (Memory Recall)

  1. Query Analysis: The model interprets the new request and derives semantic retrieval intent.
  2. Tool Calling: A memory connector is invoked with relevant terms or an embedding-based query.
  3. Pointer Resolution: The semantic index returns one or more candidate IDs.
  4. Targeted Fetch: The selected IDs are resolved against the Chat Store to retrieve exact historical payloads.
  5. Micro-Context Injection: Only the minimal historical evidence required for the current response is inserted into the dynamic prompt.
  6. Transient Cleanup: After generation, injected historical context is discarded from the active working set.

4. Data Schema — Master Node & Pointer Record

Each interaction is represented by a structured master record. The schema below separates retrieval metadata from the durable raw payload reference.

{ "turn_id": "SGO100002345", "timestamp": "2026-09-20T18:45:00Z", "domain": "#Fitness", "sub_domain": "#Recovery", "atomic_tags": ["shoulder_pain", "pushup_fatigue", "rep_40"], "micro_context": "User experienced acute anterior deltoid strain at repetition 40 of wide-grip pushups. Elbow angle recorded at 65 degrees.", "access_frequency": 3, "decay_weight": 0.96, "raw_payload_ref": "chat_store_table_row_1084" }

Field Semantics

  • turn_id — stable identifier shared by semantic and raw records.
  • timestamp — event time used for temporal filtering and chronology.
  • domain / sub_domain — hierarchical routing metadata for memory partitioning.
  • atomic_tags — compact semantic retrieval anchors.
  • micro_context — short evidence summary suitable for bounded prompt injection.
  • access_frequency — historical access signal that can influence retrieval policy.
  • decay_weight — optional recency/importance weighting signal.
  • raw_payload_ref — pointer to the durable full conversation payload.

5. Technical Implementation Framework

A practical implementation can be assembled as a modular retrieval service. The exact products are interchangeable; the architectural requirement is the separation of orchestration, semantic indexing, pointer resolution, and durable payload storage.

Chat StorePostgreSQL · MongoDB · cold storageDurable encrypted storage of raw interaction payloads

Operational Requirements

  • Stable IDs — identifiers must remain unique and resolvable across storage migrations.
  • Asynchronous indexing — semantic tagging should not unnecessarily extend the critical generation path.
  • Bounded injection — retrieval should enforce a strict evidence/token budget rather than returning unrestricted history.
  • Access controls — memory records should be isolated by user, tenant, agent, and permission domain.
  • Auditability — retrieval events should be observable so incorrect memories can be traced and corrected.
  • Encryption — raw conversational payloads should be protected at rest and in transit.

7. Conclusion & Future Scope — SMG v3

The Synapse AI Memory Graph (SMG v2) proposes a memory architecture in which long-term conversational persistence is decoupled from the LLM's active context window. The key mechanism is pointer virtualization: semantic records remain lightweight and searchable, while exact historical payloads remain external and are fetched only when required.

Under the specification, this design can support long-horizon episodic memory without continuously replaying years of dialogue into every generation request. The strongest architectural property is therefore bounded active context with demand-paged historical evidence.

SMG v3 — Lateral Memory Graph

The next iteration can introduce graph-based relationships between memory pointers. A Graph Neural Network, graph database, or learned relation layer could connect semantically or temporally related memories — for example, linking a historical shoulder pain event to a later gym routine change. This would enable controlled multi-hop reasoning across years of episodic data.

Architectural Thesis

Do not make the context window carry the entire memory system. Make the context window a bounded execution surface, and make long-term memory a searchable, addressable external system.
